# Cloudflare WARP · OpenWrt · Podkop

Отдельный WARP-туннель и русская страница LuCI для совместной работы с Podkop.
Podkop выбирает сайты, WARP обслуживает только направленный в него трафик.

**Версия 0.1.5 — экспериментальный выпуск.**
Целевая сборка: OpenWrt 24.10 с `opkg`, `aarch64_cortex-a53`.
Проверено на Redmi AX6, OpenWrt 24.10.3, Podkop 0.7.22 вместе с ByeDPI и ZeroTier.
Дополнительно проверены APK-пакеты на Cudy WBR3000UAX, OpenWrt 25.12.4.
Другие архитектуры и длительная работа на разных провайдерах не подтверждены.

## Установка и обновление одной командой

На OpenWrt с LuCI и архитектурой `aarch64_cortex-a53`:

```sh
wget -qO- https://raw.githubusercontent.com/moz9/cloudflare-warp-openwrt-podkop/main/i | sh
```

Если используется curl:

```sh
curl -fsSL https://raw.githubusercontent.com/moz9/cloudflare-warp-openwrt-podkop/main/i | sh
```

Одна команда подходит для первой установки и обновления. Автоматически
выбираются `opkg` или `apk`, устанавливаются отсутствующие зависимости,
проверяются контрольные суммы и свободное место, сохраняется резервная копия.
Первая настройка регистрирует WARP, ищет узел напрямую, запускает туннель и
проверяет HTTPS с `warp=on/plus`. При наличии Podkop создаётся пустая секция
`cfwarp`. Остаётся открыть **Службы → Cloudflare WARP**, выполнить автоподбор
и выбрать непересекающиеся списки в секции Podkop.

Существующие endpoint, регистрация, списки и намеренно выключенное состояние
WARP при обновлении сохраняются. Podkop не устанавливается автоматически:
если его нет, команда сообщает, что готов только WARP. Чужая секция `cfwarp`
не перезаписывается. Во время тестов и при несохранённых правках UCI обновление
блокируется. Недоступность Cloudflare — ошибка незавершённой настройки;
установленные пакеты остаются для диагностики и повторного запуска команды.

При наличии ZeroTier первая настройка добавляет префикс интерфейса WARP
в его исключения, сохраняя остальные параметры и шаблон router-support.
Работающий ZeroTier перезапускается один раз, только если настройки изменились.
Создание секции требует перечитывания Podkop и может кратко прервать соединения.

Резервные копии находятся в `/etc/warp/backups`. Откат файлов/пакетов при ошибке
обновления сохраняет посторонние пакеты; установленные зависимости остаются.
Для APK перед обновлением скачивается проверенный пакет предыдущей версии;
если получить его нельзя, обновление останавливается до замены приложения.

При первом подключении создаётся регистрация в сервисе Cloudflare.
[Условия Cloudflare](https://www.cloudflare.com/application/terms/).
Секреты остаются в `/etc/warp` с правами 0700/0600 и не возвращаются через RPC.

## Совместная работа

### Длительная проверка сервисов

В **Службы → Cloudflare WARP → Проверка стабильности** выберите **15, 30, 45 или
60 минут**, отметьте сервисы и нажмите **Начать проверку**. Страница может быть
закрыта: выполнение продолжается на роутере. Кнопка **Остановить** завершает
тест после текущего запроса (до 8 секунд), сохраняя частичный результат.

Доступны Google, Google AI / Gemini, ChatGPT / OpenAI, YouTube, Google Play,
Discord, Telegram и Cloudflare. Это небольшие фиксированные наборы основных
адресов сервисов. Они соответствуют сервисам каталога Podkop; Google и ChatGPT
добавлены отдельно, поскольку в текущем каталоге нет их самостоятельных списков.
Тест не обходит все домены списка и не переносит рабочие списки между секциями.

Запросы DNS и HTTPS привязаны к текущему WARP, реальные адреса исключают FakeIP.
Для каждого сервиса показаны ответы 2xx/3xx, ограничения 401/403/429, ошибки DNS,
соединения и HTTP, медианная задержка и 95-й процентиль. Перенаправление на вход
может дать 302; HTTP-ответ не подтверждает работу авторизованного чата или видео.
Отдельно считается подтверждение `warp=on/plus` через Cloudflare.

Тест делает запросы последовательно, обычно раз в минуту; не скачивает видео
и не оценивает предельную скорость. Он не меняет UCI, маршруты, endpoint или
службы. Если туннель сменился/восстановился, текущий замер заканчивается, чтобы
не смешивать результаты. Обновление пакета блокируется до завершения/остановки
теста. Последний результат хранится в RAM до нового запуска или reboot.

Это проверка стабильности текущего узла; автоматического перебора и применения
других endpoint в этой вкладке нет. Для смены узла служит существующая кнопка
**Найти другой узел**, которая может прервать соединения.

### Сетевая схема

- Userspace AmneziaWG; модуль `kmod-amneziawg` не требуется.
- Нет глобального маршрута через WARP, изменения DNS и самостоятельных правил
  перехвата трафика. Создаётся только собственная секция `network`.
- Внешние UDP-пакеты AWG получают `FwMark=2097152` (`0x00200000`) — метку
  исключения Podkop. Это предотвращает повторный захват транспорта туннеля.
  Для других систем маршрутизации значение необходимо проверить отдельно.
- Сканирование и автоподбор временно получают такое же исключение для внешних
  UDP-пакетов к пулам WARP. Иначе списки подсетей Cloudflare в Podkop могут
  отправить сам тест через другой прокси и дать неверные результаты подбора.
  Временное правило удаляется после операции; настройки firewall не меняются.
- Страница LuCI запускает длительные операции в фоне, блокирует повторный запуск
  и показывает результат. Регистрация и сканирование ограничены по времени.
- Проверка существующей секции идемпотентна; одноимённая чужая секция не затирается.
  Существующие MAIN/ByeDPI и их списки не редактируются.
- Подключение секции перечитывает Podkop; это может кратковременно прервать
  его соединения. Подключение/смена туннеля перечитывает netifd.
- При выключенном WARP выбранный трафик не переключается автоматически на WAN.
  Это поведение проверено для нового HTTPS-соединения через Podkop.
- Watchdog восстанавливает текущий endpoint. Поиск другого узла выполняется по
  кнопке, чтобы не запускать тяжёлое сканирование постоянно.

`colo=HEL` означает узел Cloudflare в Хельсинки, но `loc` и определяемая сайтом
страна могут остаться RU. WARP не гарантирует нужный регион или доступ к любому
географически ограниченному сервису. Фильтр стран сканера относится к узлам.

## Проверки

```sh
python tests/test_ipk.py
python scripts/build_apk.py
python tests/test_apk.py
python tests/test_stability.py
sh tests/router-safety.sh
```

Первый набор выполняется после сборки IPK. Второй предназначен для роутера с
уже установленным и работающим WARP; он не регистрирует новый аккаунт и не
перезапускает WAN. [Результаты и ограничения](docs/VALIDATION.md).

## Отключение и удаление

Кнопка **Отключить** останавливает WARP, сохраняя регистрацию и списки Podkop.
Для полного удаления сначала удалите секцию `cfwarp` в Podkop и примените
изменения, затем удалите регистрацию:

```sh
/usr/libexec/warp-manager unregister
opkg remove luci-app-warp warp-warpscout warp-awg
```

Менеджер откажется удалять интерфейс, пока Podkop ссылается на него.
Не восстанавливайте старую общую конфигурацию поверх новых пользовательских
изменений; резервные копии содержат приватные настройки роутера.

## Сборка

`scripts/build_ipk.py` собирает пакеты в `dist-podkop` на Windows и Linux.
Требуются Python 3.14 для подготовки исходных APK и Zig 0.15.2 для статического
ARM64-контроллера. `scripts/prepare_backend.py` извлекает только проверенные
бинарные компоненты исходного релиза, сохраняя их контрольные суммы.

```sh
python scripts/prepare_backend.py --zig /path/to/zig
python scripts/build_ipk.py --backend .build/backend
python tests/test_ipk.py
```

## Автоподбор

В **Службы → Cloudflare WARP → Автоподбор** выберите сервисы и общий бюджет
времени: 15, 30, 45 или 60 минут. Сравниваются шесть сочетаний текущего узла,
другого порта, другого адреса Cloudflare и двух значений числа маскирующих
пакетов. MTU и маскирующее имя остаются текущими. Это ограниченный поиск,
а не гарантия лучшего результата среди всех узлов Cloudflare.

Проверки идут через отдельный локальный SOCKS-прокси с отдельной регистрацией.
Рабочий туннель, списки, DNS и маршруты не переключаются. Исключения стран/узлов
учитываются предварительным отбором. Не прошедшие отбор варианты пропускаются,
поэтому подбор может закончиться раньше выбранного времени.

Рейтинг предпочитает кандидатов с минимум тремя полными кругами и успешными
подтверждениями WARP; далее сравнивает долю успешных HTTP-ответов, ошибки,
скорость и задержку. 401/403/429 показаны отдельно. Скорость измеряется двумя
файлами по 1 МиБ на вариант, до 12 МиБ за запуск; это ориентир, не предел
канала и не гарантия воспроизведения видео или работы авторизованного чата.

Кнопка **Применить** переключает только существующий WARP и проверяет HTTPS.
Возможен краткий разрыв WARP. При отказе возвращается прежняя конфигурация;
она также сохраняется в `/etc/warp/autotune-previous.conf`. Автоматически
победитель не применяется. Повторное применение после изменения настроек
требует нового подбора. Остановка сохраняет частичные результаты без права
их применения. Результаты в памяти исчезают после перезагрузки.
