# Проверка 0.1.3

2026-09-07, Redmi AX6 / OpenWrt 24.10.3 / Podkop 0.7.22.

- Автоподбор запущен из LuCI с бюджетом 15 минут и восемью сервисами.
  Завершился за 604 секунды: четыре кандидата проверены по 150 секунд,
  ещё два отклонены предварительной проверкой с исключениями RU/DME.
- 240 запросов: 200 успешных HTTP, 40 ограничений ChatGPT/OpenAI (403),
  сетевых/DNS/прочих HTTP-ошибок нет. WARP подтверждён 20 из 20 раз.
- В этом прогоне лидер: 162.159.192.55:500, Jc=6; ограниченный замер
  8.06 Мбит/с против 5.03 Мбит/с исходного варианта. Это малые загрузки,
  не предел канала; другой запуск может дать иной рейтинг.
- Контрольные суммы конфигураций и PID Podkop, ByeDPI, ZeroTier сохранены.
  Тестовый прокси завершился и освободил порт. Рабочий WARP не переключался.
- Проверены остановка и частичный отчёт, отказ повторного/параллельного
  запуска, сортировка стабильного/быстрого/заблокированного/неполного результата.
- Применение, отказ HTTPS, откат, устаревшая конфигурация и SIGKILL проверены
  реальным диспетчером на роутере с подставными файлами и контроллером.
  Переключение реального WARP на другого победителя не выполнялось.
- Регрессия обычной проверки: четыре длительности с ускоренными часами,
  остановка, смена туннеля, классификация HTTP и публичных IP прошли на BusyBox.
- Локально: 5 тестов упаковки/синтаксиса, 3 классификации, 3 рейтинга.
  LuCI: запуск, прогресс, блокировка применения до конца, мобильная таблица.

MTU в тестовом SOCKS задаётся самим движком и не перебирается. Результат
подбора требует проверки после применения в рабочем интерфейсе. Реальные
30/45/60-минутные прогоны автоподбора и клиентское воспроизведение видео
не выполнялись. При проверках повторялись краткие тайм-ауты удалённого SSH;
LuCI оставался доступен, PID служб не изменились. Причина нестабильности
ZeroTier по-прежнему отдельно не установлена.

[Результаты автоподбора](validation/autotune-20260907.json).

# Проверка 0.1.2

2026-09-07, Redmi AX6 / OpenWrt 24.10.3 / Podkop 0.7.22.

- Реальный тест: 15 минут, 15 кругов, 180 запросов по восьми профилям;
  15 из 15 подтверждений WARP, ошибок DNS/соединения/HTTP нет.
  ChatGPT/OpenAI: 30 ответов 403, отдельно от транспортных ошибок.
- 30/45/60 минут проверены с ускоренными часами на BusyBox, полного
  прогона этих длительностей пока не было. Проверены остановка,
  смена туннеля, повторный запуск, запрет обновления во время теста.
- В LuCI проверены запуск, сохранение прогресса после закрытия страницы,
  завершение и возвращение кнопок в исходное состояние.
- После теста проверены неизменность конфигураций и PID Podkop, ByeDPI,
  ZeroTier. Обновление панели также сохранило эти процессы и туннель.
- Пункт Cloudflare WARP перенесён в «Службы»; мобильная таблица получила
  подписи значений. Пакет и синтаксис: 5 тестов; подсчёт результатов: 3 теста.

После завершения прогона временно пропал удалённый доступ через ZeroTier.
Он восстановился самостоятельно. Роутер не перезагружался (uptime 31 день),
PID служб сохранились. В журнале ZeroTier есть повторяющиеся `connect:
Operation timed out`, в том числе до начала теста. Причина перерыва пока
не установлена; это не подтверждённая перезагрузка Podkop и не доказанная
связь с тестом. Длительное воспроизведение видео и работа авторизованных
AI-сервисов этой проверкой не подтверждаются.

[Результаты](validation/stability-20260907.json).

# Проверка 0.1.1

2026-09-07, тот же Redmi AX6 / OpenWrt 24.10.3 / Podkop 0.7.22.
Это целевой opkg-выпуск; унаследованные APK-сценарии не являются его проверкой.

| Сценарий | Результат |
|---|---|
| Сборка, формат IPK, пути, права, JS/shell синтаксис | 4 проверки Python прошли |
| Общая блокировка WARP, вложенный процесс, одновременный запрос | Проверено на BusyBox; исправлена передача через `/var/lock` symlink |
| Принудительное завершение владельца блокировки | Следующий процесс получает блокировку без удаления lock-файла |
| Общая блокировка подписок/DNS | Чужой владелец/неполная запись не перезаписываются |
| Отказ обновления при нехватке flash | До изменения файлов и остановки служб |
| Обновление панели при работающем WARP | Backend не переустановлен; конфигурации и прочие процессы сохранены |
| Искусственный отказ проверки после установки | Восстановлены файлы, метаданные opkg, watchdog; HTTPS WARP доступен |
| Асинхронное задание «Проверить выход» | Доходит до `checked`, блокировка освобождается |
| Отключение дважды, включение, восстановление текущего узла | Успешно; регистрация и чужие конфигурации сохранены |
| Повторное добавление существующей секции | `already_attached`, без перезаписи |
| Удаление регистрации при привязанной секции Podkop | Отказ `podkop_section_attached` |
| Искусственный отказ HTTPS при включении | Восстановлен прежний рабочий туннель |
| Список сохранения sysupgrade | Учитывает UCI, аккаунт и AWG-конфигурацию; сама перепрошивка не выполнялась |
| ZeroTier local.conf | Сохранены ключи и исключения; повторное объединение идентично; неверные типы отклоняются |
| ZeroTier после исключения WARP | ONLINE, прежняя сеть и адреса, новое SSH-подключение; нет UDP-сокетов на WARP-адресах |
| Podkop FakeIP → WARP | `warp=on`; при отключённом WARP прямого выхода нет; после включения работает |
| ByeDPI параллельно | SOCKS → YouTube HTTPS: HTTP 204 |
| LuCI после финального обновления | Кнопка проверки обновляет подтверждение WARP; кнопки разблокируются; ошибок JS нет |

Финальная установка 0.1.1 в 18:09 не изменила PID туннеля, sing-box, ByeDPI
и ZeroTier. После завершения тестов пользователь сообщил о высокой скорости
YouTube через cfwarp на реальном устройстве. Это пользовательское наблюдение,
а не завершённая проверка длительного воспроизведения. Обрыв во время тестов
совпал с запланированными reload Podkop; последний — 18:07:24–18:07:32.

При проверке полного reload обнаружена повторная загрузка подписок с временной
недоступностью DNS. Применение секции WARP и откат переведены на
`PODKOP_SUBSCRIPTION_CACHE_ONLY=1 PODKOP_SKIP_LIST_UPDATE=1`, поддерживаемые
установленным патчем Podkop. Это использует существующий кэш подписок;
добавление новых источников не входит в операцию CF WARP.
Повторный тест с кэшем прошёл: FakeIP/WARP, отсутствие прямого выхода,
восстановление и удаление только тестового домена. Пользовательский community
список YouTube в cfwarp сохранён. Полный reload всё равно прерывает текущие
соединения sing-box; такой тест требует окна обслуживания.

Изменение ZeroTier находится в отдельном репозитории
[zerotier-router-support](https://github.com/moz9/zerotier-router-support).
Использован документированный
[interfacePrefixBlacklist](https://docs.zerotier.com/config/).
Проверка касается UDP-сокетов и доступности текущей сети; принудительный TCP relay
и все возможные топологии ZeroTier не моделировались.

Неподтверждённые сценарии: физический LAN/Wi-Fi клиент, непрерывное видео,
сутки нагрузки, отключение WAN, reboot/sysupgrade, новая регистрация с нуля
на 0.1.1, другие архитектуры/прошивки/провайдеры. Не выполнялись сброс аккаунта
и разрушительные тесты рабочего роутера. Непересекающиеся рабочие списки
пользователя и их порядок сохранены.

## Предыдущая проверка 0.1.0

Дата: 2026-09-07. Redmi AX6, OpenWrt 24.10.3, kernel 6.6.104,
ARM64 cortex-a53, Podkop 0.7.22, действующие ByeDPI и ZeroTier.

Подтверждено живыми проверками:

- Регистрация через WARPSCOUT, подбор AWG endpoint и `warp=on` через HTTPS.
- Внешний socket mark: 2097152.
- Доменный маршрут: DNS/FakeIP → Podkop TPROXY → cfwarp-out → warp → HTTPS,
  результат `warp=on`, узел HEL, `loc=RU`.
- Отключение и включение кнопками в LuCI. При отключении проверочный домен
  недоступен через Podkop, после включения снова доступен через WARP.
- Параллельная проверка YouTube через ByeDPI: HTTP 204; ZeroTier ONLINE.
- Искусственный отказ HTTPS-проверки в менеджере: возвращается ошибка,
  восстанавливается прежний туннель, контрольные суммы network/podkop/firewall/
  dhcp/byedpi совпадают со снимком до теста.
- Блокировка несохранённых UCI-изменений, отклонение недопустимых и повторных
  FwMark, тайм-аут дочернего процесса, отрицательная проверка отсутствующего
  интерфейса.
- IPK: формат OpenWrt, каталоги-предки, права исполнения, LF в манифестах,
  контрольные суммы всех установленных файлов.
- Смена endpoint кнопкой LuCI и отказ второго параллельного запуска.
- Короткий тест: 18/18 HTTPS-запросов через FakeIP/Podkop/WARP за примерно
  три минуты; загрузка 3 000 000 байт через WARP — HTTP 200, около 12,8 Мбит/с.
  Это единичный замер, не оценка предельной скорости роутера или провайдера.
- Отдельный HTTPS-запрос через существующую секцию MAIN — HTTP 204.
- Искусственная ошибка контрольной суммы установленного файла при повторной
  установке: установщик отказался принять обновление, восстановил прежние файлы
  и записи трёх пакетов opkg; прежний WARP снова прошёл HTTPS-проверку.

Не подтверждено: физический клиент за LAN/Wi-Fi, непрерывное воспроизведение
видео, игровая нагрузка, перезагрузка роутера, длительная стабильность,
другие модели/провайдеры/архитектуры и OpenWrt с APK. Проверка цепочки TPROXY
выполнена запросом с самого роутера к выданному FakeIP.

Существующие firewall, DHCP и ByeDPI конфигурации оставлены без изменений.
MAIN и BYEDPI не переназначались. Временный проверочный домен удаляется из
новой секции после завершения проверки; выбор рабочих списков остаётся пользователю.
