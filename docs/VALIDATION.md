# Проверка 0.1.0

Дата: 2026-09-07. Redmi AX6, OpenWrt 24.10.3, kernel 6.6.104,
ARM64 cortex-a53, Podkop 0.7.22, действующие ByeDPI и ZeroTier.

Подтверждено живыми проверками:

- Регистрация через WARPSCOUT, подбор AWG endpoint и `warp=on` через HTTPS.
- Внешний socket mark: 2097152.
- Доменный маршрут: DNS/FakeIP → Podkop TPROXY → cfwarp-out → warp → HTTPS,
  результат `warp=on`, узел HEL, `loc=RU`.
- Отключение и включение кнопками в LuCI. При отключении проверочный домен
  недоступен через Podkop, после включения снова доступен через WARP.
- Параллельная проверка YouTube через ByeDPI: HTTP 204; ZeroTier ONLINE.
- Искусственный отказ HTTPS-проверки в менеджере: возвращается ошибка,
  восстанавливается прежний туннель, контрольные суммы network/podkop/firewall/
  dhcp/byedpi совпадают со снимком до теста.
- Блокировка несохранённых UCI-изменений, отклонение недопустимых и повторных
  FwMark, тайм-аут дочернего процесса, отрицательная проверка отсутствующего
  интерфейса.
- IPK: формат OpenWrt, каталоги-предки, права исполнения, LF в манифестах,
  контрольные суммы всех установленных файлов.
- Смена endpoint кнопкой LuCI и отказ второго параллельного запуска.
- Короткий тест: 18/18 HTTPS-запросов через FakeIP/Podkop/WARP за примерно
  три минуты; загрузка 3 000 000 байт через WARP — HTTP 200, около 12,8 Мбит/с.
  Это единичный замер, не оценка предельной скорости роутера или провайдера.
- Отдельный HTTPS-запрос через существующую секцию MAIN — HTTP 204.
- Искусственная ошибка контрольной суммы установленного файла при повторной
  установке: установщик отказался принять обновление, восстановил прежние файлы
  и записи трёх пакетов opkg; прежний WARP снова прошёл HTTPS-проверку.

Не подтверждено: физический клиент за LAN/Wi-Fi, непрерывное воспроизведение
видео, игровая нагрузка, перезагрузка роутера, длительная стабильность,
другие модели/провайдеры/архитектуры и OpenWrt с APK. Проверка цепочки TPROXY
выполнена запросом с самого роутера к выданному FakeIP.

Существующие firewall, DHCP и ByeDPI конфигурации оставлены без изменений.
MAIN и BYEDPI не переназначались. Временный проверочный домен удаляется из
новой секции после завершения проверки; выбор рабочих списков остаётся пользователю.
