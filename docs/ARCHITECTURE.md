# Implementation notes

The Go backends are pinned to BAzeRlok v3.0.0 release APK contents. IPK packaging
uses an outer gzip/tar container accepted by OpenWrt opkg, explicit parent
directories and executable modes. `FILES.sha256` checks the actual installation,
since opkg can report individual extraction errors without a nonzero exit code.

`warp-awgctl` extends the upstream strict UAPI controller with optional FwMark.
Duplicate, malformed or out-of-range marks are rejected before opening a socket.
The configuration generated by `warp-manager` sets 2097152, which the tested
Podkop rules recognize as bypass. No new firewall marking chain is installed.

`warp-common` coordinates jobs, direct manager calls, watchdog recovery, attach
and the installer using one kernel flock. The lock inode is never removed.
Its canonical path matters on OpenWrt, where /var/lock is a symlink. FD 9 passes
from the job launcher into its detached worker and nested manager. A process
death releases ownership; PID/start-time records remain only job metadata and
an old-version migration guard. Only fixed actions are accepted by rpcd.

`warp-limit` places a subprocess in a separate session, bounds registration and
scan duration, sends TERM then KILL to the owned process group. Scanner workers
are sequential by default with GOMAXPROCS=1 and a 40 MiB Go heap target. This is
a soft heap target, not a hard RSS limit. Standalone preflight tests must still
check available RAM and sustained CPU usage.

`warp-podkop` creates an empty cfwarp section only after a live WARP probe.
It rejects pending UCI edits, records a backup, uses a private UCI staging
directory and compares the original file before commit. A failed reload rolls
back only while the post-commit hash is unchanged. Arbitrary concurrent root
edits cannot be made transactionally safe by a shell script; later edits are
preserved rather than overwritten.
The attach transaction participates in the existing Podkop subscription/DNS
directory and legacy-file ownership protocol. Cached reload avoids downloading
unrelated subscriptions. A full Podkop reload still interrupts connections.

The installer skips byte-identical backends, checks space before changing
services, backs up only selected package files (never directories), and restores
their individual opkg records on failure. Existing UCI conffiles belong to the
user and are not overwritten by rollback. Two completed snapshots are retained;
incomplete recovery snapshots require manual inspection. Registration and AWG
configuration are included in sysupgrade's keep list, not public packages.

Tunnel replacement retains its previous configuration/network section and
restores them on a failed readiness probe. A successful probe is HTTPS trace
with warp=on/plus, not just a recent WireGuard handshake. On disable, the
interface disappears and Podkop's bound outbound cannot route new connections
through WAN. This fail-closed behavior has a native test in the validation log.

The initial section uses the existing Podkop DNS behavior. Choosing a different
domain resolver is a separate Podkop setting. Full-tunnel routing, LAN forwarding
zones, endpoint-country guarantees, and independent sing-box instances are out
of scope.

The original SDK recipes/tests remain as upstream reference. The maintained
opkg path is `scripts/prepare_backend.py`, `scripts/build_ipk.py`,
`tests/test_ipk.py` and `tests/router-safety.sh`.
