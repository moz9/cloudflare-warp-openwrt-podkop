# Five-minute comparative autotune (0.1.11)

Quick mode screens six endpoint/Jc combinations, retains a healthy baseline and one challenger (or two challengers if the baseline fails), then runs A/B, B/A, A/B. Screening observations are excluded from finalist statistics. All selected service URLs are used; at most three bounded HEAD requests run concurrently through the isolated SOCKS peer. Existing country/node filters and independent registration remain mandatory. Failed prechecks are not evidence that an endpoint can never work.

The global monotonic deadline includes registration, screening and final visits. Registration may consume up to 60 seconds. Quick downloads have a 32 MiB / 3 second cap and uploads an 8 MiB / 3 second cap; uploads require a full acknowledged response. At most 480 MiB is transferred; payload files are never retained. Measurements are single-flow comparisons to speed.cloudflare.com, not client Ookla capacity or multi-provider validation.

Results expose arithmetic mean, median, minimum, maximum and sample count separately for upload/download. Three speed samples per direction are required for a quick recommendation. Recommendations also require three complete service rounds and WARP checks without failures. The observed median balanced throughput must exceed the runner-up by 15 percent and observed ranges must not overlap. This is a conservative heuristic, not a statistical confidence interval or long-term stability guarantee. Insufficient, comparable and server-limited outcomes are explicit. A 429 stops all further speed requests in the run and suppresses speed recommendations. Manual application retains the existing eligibility and rollback checks.

Long 15/30/45/60-minute modes retain their existing sequential service schedule, with the new distribution display and conservative recommendation gate. No default route, DNS takeover, service restart, live account reuse or automatic application is introduced.

Validation: Python quick statistics/scheduling/assessment tests, existing speed validation and ranking tests, Node initial and populated UI render tests, installer/setup tests, IPK/APK package tests. The old broad test_static.py suite has unrelated stale expectations about ACL/backend/install.sh and unavailable Windows cc/msgfmt/sh commands; it is not reported as passing.
