# Ревью кода от 2026-09-26: открытые замечания

Результат просмотра скриптов роутера, установщика, RPC, LuCI и тестов.
Код при ревью не менялся. Номера строк относятся к коммиту `3cc8155`.

Порядок работы: исправленный пункт отметьте `[x]` и укажите коммит.
Если пункт отклонён, оставьте короткое объяснение. Когда открытых пунктов
не останется, удалите этот файл и ссылку на него из `AGENTS.md`.

## Ошибки

- [ ] **1. Вариант автоподбора обходит метку исключения Podkop.**
  Если текущий узел `188.114.98.55`, запасным адресом становится
  `162.159.193.55` (`root/usr/libexec/warp-autotune:442`). Подсети
  `162.159.193.0/24` нет в наборе nft `warp_scout_route_acquire`
  (`root/usr/libexec/warp-common:31`). При включённом в Podkop списке подсетей
  Cloudflare UDP кандидатов 5–6 может уйти через другой прокси, и результат
  подбора будет ложным.
  *Исправление:* добавить `162.159.193.0/24` в набор. Лучше хранить список пулов
  в одной переменной и проверять тестом, что все адреса кандидатов автоподбора
  в него входят (`tests/test_scout_route.sh`).

- [ ] **2. `unregister` не удаляет тестовую регистрацию автоподбора.**
  `/etc/warp/autotune-account.json` — отдельная регистрация Cloudflare.
  `do_unregister` (`root/usr/libexec/warp-manager:788`) не удаляет её ни через
  API, ни на диске. Файл указан в `root/lib/upgrade/keep.d/cfwarp`, поэтому
  переживает sysupgrade.
  *Исправление:* в `do_unregister` вызвать `warp-api unregister` для этого файла
  (без `--interface`, через WAN), затем удалить его вместе с
  `autotune-previous.conf`. Ответ 404 считать успехом, как уже сделано.
  Обновить раздел удаления в README.

- [ ] **3. Исключение ZeroTier может не покрыть реальный интерфейс.**
  `prepare_zerotier` (`root/usr/libexec/warp-setup:96`) добавляет префикс
  `warp.main.interface` (по умолчанию `warp`). Если имя `warp` занято,
  `choose_interface` (`root/usr/libexec/warp-manager:423`) выбирает
  `cfwarp`…`cfwarp9`. `interfacePrefixBlacklist` сравнивает префикс, и `warp`
  не совпадает с `cfwarp`.
  *Исправление:* добавлять оба префикса, `warp` и `cfwarp`, или обновлять
  исключение после `enable` по `actual_interface`. Покрыть тестом в
  `tests/test_setup.cjs`.

- [ ] **4. `warp-manager status` может писать на флеш при каждом опросе.**
  `do_status` вызывает `validate_settings`, а тот при некорректных значениях
  вызывает `emit_error`, который пишет `/etc/warp/last_error` и завершает
  работу. LuCI опрашивает статус каждые 3 секунды
  (`htdocs/luci-static/resources/view/warp/cfwarp.js:300`). Проверки LuCI мягче,
  чем в менеджере: `datatype='hostname'` для `sni` пропускает `_` и `..`,
  `exclude_nodes` в интерфейсе не проверяется вовсе. Итог: запись на флеш
  раз в 3 секунды и ответ статуса `ok:false`.
  *Исправление:* в режиме статуса проверять настройки без записи и без выхода,
  возвращая `error_code`. В LuCI повторить регулярные выражения менеджера
  (`valid_hostname`, `valid_country_list`, `valid_node_list`).

## Тесты и CI

- [ ] **5. Часть тестов не запускается в CI; `test_static.py` уже сломан.**
  `.github/workflows/check.yml` не запускает `tests/run.sh`
  (`test_static.py`, `test_api.sh`), `test_speed.py`, `test_quick.py`,
  `node --test tests/*.cjs` и `tests/test_scout_route.sh`.
  Сейчас `python3 tests/test_static.py` даёт 3 провала и 1 ошибку:
  - `test_acl_is_minimal` ожидает только `status` в read-ACL, а там ещё
    `test_status` и `autotune_status`;
  - `test_awg_backend_is_standalone` ожидает `SCOUT_JOBS` по умолчанию 2,
    а сейчас 1;
  - `test_installer_selects_supported_arm64_packages` ищет проверку
    архитектуры в `install.sh`, а она теперь в `install-podkop.sh`;
  - `test_translations_compile` требует `msgfmt` (в CI нужен `gettext`).

  Остальные тесты на хосте проходят.
  *Исправление:* обновить `test_static.py` под текущий код, добавить все
  хостовые тесты в workflow, по возможности добавить `shellcheck`.

- [ ] **6. `overview.js`, вероятно, мёртвый код.**
  Меню указывает на `warp/cfwarp`, а сборка упаковывает только `cfwarp.js`.
  `htdocs/luci-static/resources/view/warp/overview.js` упоминается только в
  `tests/test_static.py`. Удалить файл или перевести тест на `cfwarp.js`.

## Документация и согласованность

- [ ] **7. `tests/README.md` испорчен по кодировке.** UTF-8 был прочитан как
  CP1251 и сохранён заново. Восстанавливается без потерь:
  `python3 -c "p='tests/README.md';s=open(p,encoding='utf-8').read();open(p,'w',encoding='utf-8').write(s.encode('cp1251').decode('utf-8'))"`.

- [ ] **8. Версии и списки проверок расходятся.**
  - в `Makefile` указаны `PKG_VERSION:=3.0.0` и `LUCI_URL` на upstream;
  - `dist/SHA256SUMS` перечисляет пакеты 3.0.0;
  - в `release/` заметки есть только до v0.1.5, хотя установщик ставит 0.1.11;
  - списки проверок в README, `tests/README.md` и CI не совпадают.

- [ ] **9. Старый `install.sh` слабее, чем `i`.** Работает только через curl, без
  повторных попыток и без `sh -n`. Сделать его обёрткой над той же логикой,
  что и `i`.

## Предложения (по желанию)

- [ ] **10. Закрепить установщик за релизом.** `i` скачивает `install-podkop.sh`
  из ветки `main`, поэтому любой коммит в `main` сразу попадает ко всем
  пользователям. Надёжнее брать установщик из ассетов релиза и сверять
  контрольную сумму.
- [ ] **11. Облегчить опрос из LuCI.** Каждый вызов статуса раз в 3 секунды
  запускает десятки процессов (jsonfilter ×6, awk ×9, uci, awgctl). К этому
  добавляются два запроса раз в 5 секунд для тестов. Можно опрашивать реже
  при простое, опрашивать только открытую вкладку и кешировать разбор аккаунта.
- [ ] **12. Ужесточить проверку чисел в RPC.** В
  `root/usr/share/rpcd/ucode/warp.uc` значения `minutes` и `candidate`
  проверяются нестрогим `!=`, но в строку `popen` подставляются в исходном
  виде. Нужны права записи в ACL, так что риск низкий. Лучше проверять
  `type(x) == 'int'` и подставлять уже приведённое значение.
